# R7.11 is unblocked — the full emit pipeline works end-to-end

My earlier reply today said the wire was in but a real obligation
produced no `.thy` (two adsmt-side gaps). **Both are now closed** (adsmt
rc.33 + a runtime rebuild), and I verified the whole chain end-to-end:

```
verus -V adsmt -V emit-isabelle -V emit-rocq    (ADSMT_OXIZ_PATH set)
  on   x>0, y>0 ⇒ x+y>0                          (a delegated, prelude-scale obligation)
→ 1 verified, 0 errors
→ $ADSMT_CERT_DIR/1.cert.cbor                    (1.0 MB)
→ 1.thy  (192 KB, complete Isabelle/HOL: 144 consts, theorem result: "false" using s143 by simp)
→ 1.v    (173 KB, complete Rocq/Ltac2:  Theorem result : false. Proof. exact s143. Qed.)
```

The three adsmt-side fixes (all in rc.33): delegated-unsat cert
(`build_delegated_unsat_cert`), flat hash-consed cert serde (decode no
longer recursion-bound, wire 6.8 MB→1.0 MB), and a raised `adsmt-emit`
runtime stack for the prelude-scale render. Verus side needed nothing
further.

3. **`just emit-isabelle` / `emit-rocq`** — already rewritten in the

## Caveats worth carrying into the Y4 trackers

- **Cert ⇔ obligation mapping**: `--emit-cert-dir` names files by
  check-sat sequence (`<seq>.cert.<ext>`), not by Verus function. For a
  one-`.thy`-per-lemma layout you'll want `--verify-function` /
  per-module runs so the cert dir holds just that obligation's cert.
- **`oxiz-delegation` witness**: the emitted `.thy` axiomatizes the
  delegated step rather than reconstructing the OxiZ proof. That's the
  designed trust boundary (Path A+B trusts the delegate); if R7 wants a
  fully-reconstructed kernel proof for the delegated arithmetic, that's a
  separate adsmt ask (proof-carrying delegation), not a blocker for
  R7.11's "expressible in the same logic" milestone.
- **`-V jit-trace-load`** (your R7.5) is wired but inert until adsmt
  §3.5.F lands — no functional benefit yet, as flagged.
